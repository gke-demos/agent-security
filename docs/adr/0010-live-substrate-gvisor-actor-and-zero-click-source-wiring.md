# Live Agent Substrate gVisor Actor Execution and Zero-Click External Source Auto-Discovery

AegisSRE verifies and executes untrusted repository test suites against the live GKE cluster's `WorkerPool/aegis-remediator-pool` (`ate.dev/worker-pool=aegis-remediator-pool`, `SandboxConfig/gvisor-default`) by combining `kubectl` and `kubectl-ate` inspection (`get actors` and `get egress-policy default` in atespace `aegis-system`) with a built-in `--mode=remediator-actor` HTTP mode (`/sandbox/execute` and `/healthz`) on `aegis-server` that runs inside a gVisor guest `Actor` (`ActorTemplate/sandbox-remediator-v1`), proving zero-3LO-secret `os.Environ()` isolation, capturing the `/proc/version` `runsc` kernel signature, and probing `atenet` Egress MITM (`https://evil.example.com/exfil` blocked vs. `https://api.github.com` allowed). To enable zero-click `6/8` `LIVE` operation from standard `gcloud`, `kubectl`, and `gh` developer sessions while supporting `8/8` `LIVE` operation with SaaS credentials, `ConfigFromEnv()` auto-defaults regional `ModelArmorEndpoint` (`aegis-prompt-screen`), `DLPEndpoint`, and `agentregistry.googleapis.com/v1alpha` `AgentRegistryURL` whenever `GOOGLE_CLOUD_PROJECT` is set, auto-resolves `gh auth token` when `LIVE_GITHUB=true`, attaches `x-goog-user-project` on outbound Google Cloud ADC requests, and accepts optional `Gmail` (`ALICE_GMAIL_TOKEN` / `--with-gmail`) and `Atlassian Jira Cloud` (`JIRA_BASE_URL` + `ALICE_JIRA_TOKEN` / `BOB_JIRA_TOKEN`) tokens via environment variables or runtime `POST /api/sessions/{sessionId}/oauth/grant` grants.
